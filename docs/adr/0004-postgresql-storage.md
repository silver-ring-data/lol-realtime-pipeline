# 0004. 데이터 저장소로 PostgreSQL 선정

## 현상

- 본 프로젝트는 정형 데이터(경기 지표)와 비정형 데이터(채팅 로그)를 실시간으로 결합하고 분석해야 함.
- 특히 롤 인게임 데이터는 복잡한 계층 구조를 가진 JSON 형식이 많아, 이를 유연하게 처리하면서도 강력한 관계형 쿼리(Join) 성능을 보장하는 저장소가 필요함.

## 결정

- 범용 RDBMS 중 하나인 MySQL 대신, **PostgreSQL 15 이상** 버전을 기본 데이터베이스로 채택함.

## 이유

- **JSONB 타입 지원:** 롤 API의 복잡한 JSON 데이터를 `JSONB` 형식으로 저장하여 인덱싱을 처리할 수 있음. 이는 데이터 구조 변경에 유연하게 대응하면서도 조회 속도를 보장함.
- **고급 윈도우 함수 (Window Functions):** "최근 10초간의 골드 변화량"이나 "분당 채팅 화력" 등 시계열 통계 데이터를 계산할 때 MySQL보다 정교하고 빠른 연산이 가능함.
- **데이터 무결성 및 정합성:** 비정형 채팅 데이터와 정형 경기 데이터를 Join 할 때 높은 일관성을 유지하며, 복잡한 실행 계획(Execution Plan) 최적화 능력이 뛰어남.

## 트레이드오프

- **장점:** 데이터 스키마 확장이 용이하고, 복잡한 실시간 분석 쿼리를 DB 레벨에서 효율적으로 처리 가능함.
- **단점:** MySQL에 비해 설정이 다소 복잡할 수 있으나, Airflow 및 Spark와의 호환성이 뛰어나 운영상의 이점이 더 큼.
