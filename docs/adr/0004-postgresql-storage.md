## 배경

정형 데이터(경기 지표)와 비정형 데이터(채팅 로그)를 실시간으로 결합·분석해야 한다. 인게임 데이터는 계층 구조를 가진 JSON 이 많아, 이를 유연하게 다루면서도 관계형 조인 성능을 보장하는 저장소가 필요하다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. PostgreSQL 15 이상 | JSONB 타입·인덱싱, 고급 윈도우 함수, Airflow·Spark 호환성 | MySQL 보다 설정이 다소 복잡 |
| B. MySQL | 범용적, 설정 단순 | JSON 처리·윈도우 함수가 상대적으로 약함 |

## 결정

**A 를 채택한다.** JSONB 로 복잡한 JSON 을 저장·인덱싱하고, "최근 10초간 골드 변화량", "분당 채팅 화력" 같은 시계열 통계를 윈도우 함수로 계산한다.

## 결과

- 좋아지는 것: 스키마 확장이 쉽고, 복잡한 실시간 분석 쿼리를 DB 레벨에서 효율적으로 처리한다.
- 감수하는 것: 설정 복잡도.
- 다시 볼 조건: 트랜잭션이 필요한 관계형 데이터가 실제로 있는지 재확인할 때. (0029 에서 RDS 제거로 폐기되었다.)
