# 0003. 변동성에 따라 파이프라인을 단계별로 검증한다 (정적 경기 vs 극적 경기)

## 배경

실시간 스트리밍 시스템은 데이터 변동성(Volatility)에 따라 처리 성능이 달라진다. 시스템의 기초 체력(안정성)과 한계치(부하 대응)를 모두 증명해야 한다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 정적 경기 → 극적 경기 순으로 단계 확장 | 안정적 흐름을 먼저 확보한 뒤 고도화, 스파이크 대응 능력을 시각적으로 증명 | 두 종류의 데이터셋 준비 필요 |
| B. 처음부터 복잡한 환경 구성 | 준비 단축 | 문제 원인 분리 어려움 |

## 결정

**A 를 채택한다.**

- Step 1 (운영 위주 경기): 데이터가 일정하게 들어오는 구간에서 연산 정확도를 Baseline 으로 구축한다.
- Step 2 (난전/역전 경기): 킬이 동시에 터지는 데이터 스파이크 상황에서 Kafka 와 Spark 의 부하 분산 처리 능력을 검증한다.

## 결과

- 좋아지는 것: 단계적 고도화로 엔지니어링 리스크를 낮추고, 데이터 폭주 상황의 장애 대응·최적화 능력을 증명한다.
- 감수하는 것: 검증 단계가 늘어난다.
- 다시 볼 조건: 데이터셋과 처리 엔진이 바뀔 때. (이후 데이터셋이 2024 롤드컵 결승 단일 경기로 확정되고 엔진이 Flink 로 바뀌면서 폐기되었다.)
