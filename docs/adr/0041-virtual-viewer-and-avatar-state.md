# 0041. 가상 시청자 수를 시뮬레이션하고 아바타 상태(Animation)를 점수와 동기화한다

## 배경

'디지털 트윈 응원석'에는 실시간 동시 시청자 수가 필요하지만, MVP 인 과거 VOD(2024 롤드컵 결승)에서는 초 단위 시청자 수를 API 로 구할 수 없다. 실제 결승 트래픽(약 150만~600만 명)을 아바타 수로 1:1 렌더링하면 브라우저 메모리 과부하(OOM)와 렌더링 지연이 발생한다. 교전이 없을 때 아바타가 갑자기 사라지는 것은 항상 만석인 현실 관중석과 괴리가 크다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 스케일 다운 시뮬레이션 + 점수 기반 아바타 상태 매핑 | 브라우저가 감당할 수(100~300개)만 렌더링, 군중 애니메이션으로 민심을 직관적으로 표현 | 시청자 수는 Mock 데이터 |
| B. 실제 시청자 수 1:1 렌더링 | 진실성 | 데이터 부재, OOM |

## 결정

**A 를 채택한다.**

1. 시청자 수 스케일 다운: `game_bot.py` 가 실제 트래픽의 1/100 수준(예: 3만 명)을 베이스라인으로 두고, 시간에 따라 완만히 우상향(초당 +1~5명)하다가 하이라이트 발생 시 스파이크가 튀는 Mock 데이터를 생성한다.
2. Flink `final_score`(0~100점) → 아바타 애니메이션 동기화: 0~20점(파밍)은 기본 관중석과 조용한 응원 모션, 30~60점(대치)은 스탠딩과 빠른 응원봉 모션, 80점 이상(한타)은 전원 점프·불꽃/오라 이펙트·카메라 쉐이크.

## 결과

- 좋아지는 것: 프론트엔드 성능 안정성, 숫자 텍스트가 아닌 군중 애니메이션으로 Flink 결과를 증명.
- 감수하는 것: 시청자 수가 실제 데이터가 아니다 (0022 의 '실제 데이터만 사용' 원칙과 상충하여 보류 상태).
- 다시 볼 조건: 실시간 시청자 수 API 연동이 가능해질 때.
