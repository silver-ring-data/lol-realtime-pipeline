# 0041. 가상 시청자 수 시뮬레이션 및 아바타 상태(Animation) 동기화 전략

> 원본: https://app.notion.com/p/3551198df8d980f7a14cdf0fd5feb73a

| 상태 | 날짜 |
|---|---|
| 보류 | 2026-05-03 |

## 현상

- **데이터 부재:** '디지털 트윈 응원석'을 구현하기 위해서는 실시간 동시 시청자 수 데이터가 필요하지만, MVP 모델인 과거 VOD(2024 롤드컵 결승)의 경우 초 단위 시청자 수 지표를 API로 구할 수 없음.
- **프론트엔드 성능 한계:** 실제 롤드컵 결승전 트래픽(약 150만~600만 명)을 화면의 아바타 숫자로 1:1 대응하여 렌더링할 경우, 웹 브라우저의 메모리 과부하(OOM) 및 렌더링 지연이 발생함.
- **UX/UI 어색함:** 교전이 없을 때 시청자(아바타)가 갑자기 증발하는 것은 현실의 관중석(항상 만석 유지)과 괴리감이 큼.

## 결정

실제 데이터의 한계를 극복하고 브라우저 렌더링 부하를 줄이기 위해 '스케일 다운(Scale-down) 시뮬레이션'과 '점수 기반 상태 매핑'을 도입함.

1. **시청자 수 스케일 다운 및 곡선 시뮬레이션:**
   - 파이썬 봇(`game_bot.py`)이 실제 트래픽의 1/100 수준(예: 3만 명)을 베이스라인으로 설정함.
   - 시간에 따라 완만하게 우상향(초당 +1~5명)하다가, 교전(하이라이트) 발생 시 스파이크가 튀는 로직을 추가하여 가짜(Mock) 데이터를 자연스럽게 생성.
2. **Flink 하이라이트 점수 ➔ 아바타 애니메이션 동기화:**
   - 아바타의 '숫자'를 무한정 늘리는 대신, 아바타의 '행동 상태(State)'를 변경하여 현장감을 부여함.
   - Flink가 연산한 `final_score`(0~100점)를 프론트엔드로 전송:
     - **0~20점 (파밍):** 기본 관중석 유지, 조용한 응원 모션
     - **30~60점 (대치):** 스탠딩 및 빠른 응원봉 모션
     - **80점 이상 (한타):** 전원 점프, 불꽃/오라 이펙트 및 카메라 쉐이크(화면 흔들림) 적용

## 이유

- **성능 안정성:** 브라우저가 감당할 수 있는 적정 수(예: 100~300개)의 아바타만 렌더링하여 프론트엔드 최적화 달성.
- **시각적 임팩트 극대화:** 단순한 '숫자 텍스트'가 아닌, 아바타의 군중 애니메이션을 통해 Flink가 계산한 '민심(채팅 화력+이벤트)'의 결과를 가장 직관적으로 증명 가능.
