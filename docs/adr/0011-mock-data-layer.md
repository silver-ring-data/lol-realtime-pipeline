## 현상

- **외부 API 의존성:** 치지직 및 Riot API는 호출 횟수 제한(Rate Limit)이 존재하며, 네트워크 상태에 따라 데이터 공급이 불안정할 수 있음.
  - 실제 API를 직접 연결하여 개발할 경우, 로직 에러로 인한 무한 루프 발생 시 API 계정 차단(Ban) 리스크가 있음.
- **테스트 환경의 한계:** 실제 경기 데이터는 특정 시간에만 발생하므로, 개발 및 디버깅 시 원하는 시점에 대량의 데이터를 확보하기 어려움.
  - 초당 수천 건 이상의 채팅이 쏟아지는 '폭주 상황'에 대한 파이프라인 부하 테스트를 실제 데이터만으로는 수행할 수 없음.

## 결정

- **Faker 라이브러리 활용:** 실제 데이터 스키마와 동일한 구조의 가짜 데이터(Mock Data) 생성 로직을 구축함.
- **Staging 환경 운영:** 데이터를 S3 및 DB에 적재하기 전, 가짜 데이터를 활용해 전반적인 파이프라인 흐름(Airflow -> S3 -> Postgres)을 먼저 검증함.
- **Data Lake (S3) 활용:** 생성된 Raw Data는 AWS S3에 JSON 형태로 우선 적재하여 '데이터 재처리(Reprocessing)' 역량을 확보함.

## 트레이드오프

- **장점:**
  - **내결함성 확보:** API 장애나 네트워크 단절 상황에서도 독립적인 개발 및 테스트 가능.
  - **부하 테스트 가능:** 임의의 대량 데이터 생성을 통해 시스템의 병목 구간을 사전에 파악할 수 있음.
  - **비용 절감:** 불필요한 API 호출을 줄여 할당량 관리 및 잠재적 비용 낭비 방지.
- **단점:**
  - 실제 데이터와 가짜 데이터 사이의 미세한 규격 차이가 발생할 수 있으므로, 최종 단계에서 반드시 실제 API와의 정합성 테스트가 필요함.
