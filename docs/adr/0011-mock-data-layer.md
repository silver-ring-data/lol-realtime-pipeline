## 배경

치지직·Riot API 는 Rate Limit 이 있고 네트워크 상태에 따라 공급이 불안정하다. 실제 API 를 직접 연결해 개발하면 로직 에러로 무한 루프가 발생할 때 계정 차단 리스크가 있다. 또한 실제 경기 데이터는 특정 시간에만 발생하므로 원하는 시점에 대량 데이터를 확보하기 어렵고, 초당 수천 건의 '폭주 상황' 부하 테스트를 실제 데이터만으로 수행할 수 없다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. Faker 기반 Mock 데이터 + Staging 검증 | 내결함성, 부하 테스트 가능, API 호출 비용 절감 | 실제 데이터와 규격 차이 가능 |
| B. 실제 API 직접 연결 개발 | 정합성 | 계정 차단 리스크, 테스트 시점 제약 |

## 결정

**A 를 채택한다.** 실제 스키마와 동일한 구조의 Mock 데이터 생성 로직을 구축하고, S3·DB 적재 전에 전체 파이프라인 흐름(Airflow → S3 → Postgres)을 먼저 검증한다. 생성된 Raw Data 는 S3 에 JSON 으로 우선 적재하여 재처리(Reprocessing) 역량을 확보한다.

## 결과

- 좋아지는 것: API 장애·네트워크 단절 상황에서도 독립 개발이 가능하고, 병목 구간을 사전에 파악한다.
- 감수하는 것: 최종 단계에서 실제 API 와의 정합성 테스트가 반드시 필요하다.
- 다시 볼 조건: 실제 API 스키마가 변경될 때.
