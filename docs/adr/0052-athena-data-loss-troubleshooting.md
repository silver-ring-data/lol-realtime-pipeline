## 결정

**1. S3 경로 및 파일명 명명 규칙 점검 (가장 먼저 확인해야 할 사항)**

- **S3 LOCATION 디렉터리 확인:** Athena 테이블을 정의할 때 `LOCATION` 속성이 특정 파일명(예: `.../data.parquet`)을 가리키고 있지 않은지 확인하세요. 경로는 반드시 슬래시(`/`)로 끝나는 최상위 디렉터리(예: `.../data/`)로 지정되어야 합니다.
- **이중 슬래시(`//`) 제거:** S3 경로를 동적으로 생성하는 과정에서 `s3://bucket/prefix//input//`과 같이 이중 슬래시가 들어가지 않았는지 확인하세요. 엔진이 이를 인식하지 못해 데이터를 스킵할 수 있습니다.
- **숨김 파일 여부:** Glue Job이 데이터를 S3에 쓸 때 파일명이 밑줄(`_`)이나 마침표(`.`)로 시작하는지(예: `_SUCCESS`, `.part-0000`) 확인하세요. Athena는 이런 파일들을 무시하고 0건으로 처리하므로, 정상적인 영문자나 숫자로 시작하도록 파일명 생성 규칙을 수정해야 합니다.
- **컬럼명 소문자화:** 원본 JSON 데이터의 키 값에 카멜 표기법(CamelCase)이나 하이픈()이 포함되어 있는지 확인하세요. Athena와 Glue는 소문자와 언더스코어(`_`)만 허용하므로, 이를 위반할 경우 매핑에 실패합니다.

**2. 메타데이터 파티션 동기화 (S3 파일과 카탈로그의 불일치 해결)**

데이터가 S3에 쌓이더라도 Athena가 이를 인식할 수 있도록 파티션을 추가해 주어야 합니다.

- **Hive 스타일 경로일 경우:** S3 경로가 `year=2026/month=05/` 형태라면, Athena 쿼리 편집기나 Airflow에서 `MSCK REPAIR TABLE 테이블명;`을 실행하여 카탈로그를 동기화해 보세요.
- **일반 디렉터리 경로일 경우:** S3 경로가 단순 날짜 형태(`2026/05/`)라면 `MSCK REPAIR`가 작동하지 않습니다. 이 경우 `ALTER TABLE ADD PARTITION` 명령어로 물리적 위치를 명시적으로 직접 추가해 주어야 합니다.
- **권장 해결책:** Airflow로 매번 파티션을 갱신하기보다, Athena 테이블 생성 시 **파티션 프로젝션(Partition Projection)** 속성을 설정하여 엔진이 자동으로 S3 경로를 계산하고 스캔하게 만드는 방식을 시도해 보세요.

**3. Airflow DAG의 실행 타이밍(Race Condition) 조정**

- Airflow에서 Glue Job을 트리거한 후, Job이 S3에 Parquet 파일 쓰기를 완벽히 마친 상태(`SUCCEEDED`)가 될 때까지 기다리는 센서(Sensor)나 폴링(Polling) 대기 로직이 있는지 점검하세요.
- 파일 생성이 완료되기 전에 Athena가 쿼리를 먼저 실행하거나 파티션을 스캔하도록 파이프라인이 짜여 있다면, S3 빈 경로를 스캔하여 결과적으로 빈 헤더만 반환하게 됩니다.

**4. Parquet 스키마 강제 매핑 및 통계 무시 옵션 적용**

채팅봇/게임 봇 특성상 데이터 스키마(구조)가 수시로 변할 수 있습니다.

- **인덱스 기반 매핑:** Athena 테이블 속성(`TBLPROPERTIES`)에 `'parquet.column.index.access'='true'`를 추가해 보세요. 이름이 아닌 컬럼의 물리적 순서를 기준으로 읽어 들여 스키마 충돌을 방지할 수 있습니다.
- **통계 최적화 무시:** 테이블 서데(SerDe) 속성에 `'parquet.ignore.statistics'='true'`를 추가해 보세요. Parquet 파일 내부에 기록된 잘못된 통계값 때문에 데이터 스캔 자체를 건너뛰는 현상을 막아줍니다.

**5. 가장 앞단의 데이터 유실 (Data Drop) 검증**

- 결과물인 S3의 Parquet 파일을 다운로드하여 로컬이나 다른 툴(예: Apache Drill 등)로 열어보세요.
- Kinesis에서 유입된 원본 JSON 데이터가 규격에 맞지 않아서, 중간에 있는 Glue Job이 변환 과정 중 행(Row) 데이터를 전부 버리고 **메타데이터(컬럼 구조)만 있는 0바이트 혹은 껍데기 Parquet 파일**을 생성했을 가능성을 배제할 수 없습니다.
