# 0052. Athena 데이터 유실 문제의 점검 절차를 정한다

> 원본: https://app.notion.com/p/3591198df8d980b1a09ee53fba49beb5
> 노션 번호는 "ADR-051" 이며, 마이그레이션 시 0052 로 재번호했다.

| | |
|---|---|
| 상태 | **채택** |
| 날짜 | 2026-05-07 |
| 결정자 | silver-ring-data |
| 관련 | 0035, 0046, 0047 |

## 배경

Glue Job 이 S3 에 쓴 Parquet 데이터를 Athena 로 조회했을 때 0건 또는 빈 헤더만 반환되는 데이터 유실 문제가 발생했다. 노션 원문은 결정 형식이 아니라 문제 해결 과정의 점검 목록으로 기록되어 있어, 아래에 그 절차를 옮긴다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 경로 → 파티션 → 타이밍 → 스키마 → 원본 순으로 단계별 점검 | 원인을 앞단부터 체계적으로 좁힘 | 절차가 길다 |

## 결정

**A 를 채택한다.** 점검 순서는 다음과 같다.

1. S3 경로 및 파일명 규칙: `LOCATION` 이 특정 파일이 아닌 `/` 로 끝나는 디렉터리를 가리키는지, 동적 경로 생성 시 이중 슬래시(`//`)가 들어가지 않았는지, 파일명이 `_` 나 `.` 로 시작(`_SUCCESS`, `.part-0000`)하여 Athena 가 무시하지 않는지, 컬럼명이 소문자·언더스코어만 사용하는지(CamelCase·하이픈은 매핑 실패) 확인한다.
2. 메타데이터 파티션 동기화: Hive 스타일 경로(`year=2026/month=05/`)면 `MSCK REPAIR TABLE` 로 동기화하고, 일반 디렉터리 경로(`2026/05/`)면 `ALTER TABLE ADD PARTITION` 으로 직접 추가한다. 권장은 테이블 생성 시 파티션 프로젝션(Partition Projection)을 설정하여 엔진이 자동으로 경로를 계산하게 하는 것이다.
3. Airflow 실행 타이밍(Race Condition): Glue Job 이 `SUCCEEDED` 가 될 때까지 기다리는 센서·폴링 로직이 있는지 점검한다. 파일 생성 전에 Athena 가 쿼리하면 빈 경로를 스캔한다.
4. Parquet 스키마 강제 매핑·통계 무시: 봇 특성상 스키마가 수시로 변하므로 `TBLPROPERTIES` 에 `'parquet.column.index.access'='true'` 를 추가해 컬럼 순서 기준으로 읽고, SerDe 에 `'parquet.ignore.statistics'='true'` 를 추가해 잘못된 통계값 때문에 스캔을 건너뛰는 현상을 막는다.
5. 앞단 데이터 유실 검증: 결과 Parquet 를 내려받아 다른 도구로 열어 본다. Kinesis 원본 JSON 이 규격에 맞지 않아 Glue Job 이 행을 모두 버리고 메타데이터만 있는 껍데기 Parquet 를 생성했을 가능성을 배제할 수 없다.

## 결과

- 좋아지는 것: 유실 원인을 재현 가능한 순서로 좁힐 수 있다.
- 감수하는 것: 절차 유지.
- 다시 볼 조건: 파티션 프로젝션 도입으로 2번 단계가 불필요해질 때.
