## 배경

본 프로젝트의 주된 목표는 정확도 높은 분석 모델보다 대용량 실시간 데이터의 안정적 처리(High Throughput, Low Latency)를 증명하는 것이다. 일반 Riot API(Match V5)는 실시간 대회 데이터를 제공하지 않으며, Rate Limit 때문에 모든 필드를 수집하면 리소스 낭비와 시스템 부하가 발생한다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 핵심 지표 5~6개로 수집 필드 제한 | 프리티어 환경에서 Spark 메모리 점유율 30% 이상 절감, 파이프라인 가용성·복구 속도 향상 | 초기 제외한 필드는 추후 분석에 활용하기 어려움 |
| B. 모든 필드 수집 | 사후 분석 유연성 | Rate Limit·메모리 부하, 실시간 처리 목적과 어긋남 |

## 결정

**A 를 채택한다.** 데이터의 양보다 흐름과 속도(Velocity)에 집중하기 위해 수집 필드를 제한한다.

- 정형 데이터(Riot API): `totalGold`, `killCount`, `matchId`, `gameTime`
- 비정형 데이터(Chat): `chatMessage`, `timestamp`

`matchId` 기준 멱등성(Upsert) 로직으로 중복 적재를 차단한다.

## 결과

- 좋아지는 것: 0.5초 단위로 쏟아지는 소수 정예 데이터를 처리하여 실시간 스트리밍 역량을 입증하고, 리소스를 최적화한다.
- 감수하는 것: 제외된 필드는 나중에 활용하기 어렵다. 확장성을 고려한 모듈화 설계로 보완한다.
- 다시 볼 조건: 데이터 소스가 Riot API 에서 다른 소스로 바뀌거나, 분석 요구사항이 확대될 때. (이 결정은 이후 데이터 소스 변경으로 폐기되었다.)
