# 0001. 데이터 수집 범위의 최적화 (Data Dieting) (속도 VS 양)

> 원본: https://app.notion.com/p/3411198df8d9801381fdd2fdf7be3e8a

| 상태 | 날짜 |
|---|---|
| 폐기 | 2026-04-13 |

## 현상

- 본 프로젝트는 정확도 높은 분석 모델 구축보다 **대용량 실시간 데이터의 안정적 처리(High Throughput & Low Latency)**를 증명하는 것이 주된 목표임.
- 일반적인 Riot API(Match V5)는 실시간 대회 데이터를 제공하지 않으며, API 호출 제한(Rate Limit)으로 인해 모든 필드를 수집하는 것은 리소스 낭비와 시스템 부하를 초래함.

## 결정

수집 데이터의 양보다 **데이터의 흐름과 속도(Velocity)**에 집중하기 위해 수집 필드를 핵심 지표 5~6개로 제한하는 **'Data Dieting'**을 수행함.

- **정형 데이터 (Riot API):** `totalGold`, `killCount`, `matchId`, `gameTime`.
- **비정형 데이터 (Chat):** `chatMessage`, `timestamp`.

## 이유

- **리소스 최적화:** 불필요한 필드 제거를 통해 AWS 프리티어 환경에서도 Spark 메모리 점유율을 **30% 이상 절감** 가능.
- **기술적 증명:** 0.5초 단위로 끊임없이 쏟아지는 소수 정예 데이터를 처리함으로써 **실시간 스트리밍 처리 역량**을 효과적으로 입증.
- **데이터 정합성:** `matchId` 등을 기준으로 멱등성(Upsert) 로직을 적용하여 중복 적재를 원천 차단함

## 트레이드오프

- **장점:** 데이터 파이프라인의 가용성이 높아지고, 장애 발생 시 복구가 빠름.
- **단점:** 초기 설계 단계에서 제외된 필드는 추후 분석에 활용하기 어려우나, 이는 확장성을 고려한 모듈화 설계를 통해 보완 가능함.
