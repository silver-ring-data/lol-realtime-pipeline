## 배경

Flink 에서 가공한 골드 점수와 선별 채팅을 OpenSearch 로 보낼 때 시간 필드(`ts`, `window_start`)가 Date 타입이 아닌 문자열로 인식되어 시계열 시각화가 어려웠다. Kinesis → OpenSearch 배달 Lambda 가 간헐적으로 멈췄고, CloudWatch 로그에서 `Status: timeout` 을 확인했다. 비용 때문에 OpenSearch 를 `t3.small` 로 잡아 응답이 간헐적으로 느렸다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 인덱스 템플릿 + Lambda 타임아웃·메모리 상향 + 리소스 생명주기 관리 | 매핑 자동화, 지연 시 Lambda 보호, 비용 절감 | 익일 재시작 시 수동 절차 필요 |
| B. 인덱스마다 수동 매핑, Lambda 기본값 유지 | 변경 없음 | 수천 건 채팅 상황에서 수동 매핑 불가, 타임아웃 재발 |

## 결정

**A 를 채택한다.**

- 인덱스 템플릿: 데이터 유입 전 '설계도'를 등록하여 인덱스 생성 시 매핑이 자동 적용되게 한다. 주석을 제거한 표준 JSON 으로 작성하여 Dev Tools 등록 에러를 방지한다.
- Lambda 설정: Timeout `3초 → 30초`, Memory `128MB → 256MB` 이상. 타임아웃은 '대기 시간'이 아니라 '최대 허용 시간'이므로 실시간성에 영향이 없고, 저사양 인스턴스의 간헐적 지연으로 Lambda 가 죽는 것을 막는 최소한의 보호 장치다.
- 리소스 생명주기: OpenSearch, Kinesis, Flink 는 작업 종료 후 삭제·중지하고 비용이 거의 없는 Lambda 는 유지한다. 익일 재시작 시 KDS 트리거 갱신과 인덱스 템플릿 재등록을 필수 절차로 정의한다.

## 결과

- 좋아지는 것: `date` 타입이 고정되어 대시보드 시계열 분석이 가능하고, 전송 실패가 줄어든다.
- 감수하는 것: 재시작 절차.
- 다시 볼 조건: OpenSearch 사양을 올려 지연이 사라지거나, 인프라를 IaC 로 관리하게 될 때.
