## 배경

Flink 실시간 분석과 별개로 전체 경기 결과를 정산·장기 보관하는 배치 레이어가 필요하다. 경기 중에 배치를 돌리면 데이터가 누락될 수 있으므로 반드시 '경기 종료' 확인 후 ETL 이 시작되어야 하고, 봇 실행부터 Glue 정제·Athena 리포트까지 자동화해야 한다. 또한 세트 간 휴식 시간(약 15분)보다 배치 정산이 오래 걸리면 다음 세트 수집에 지연·유실이 발생할 위험이 있다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `S3KeySensor` 종료 시그널 + 수집/분석 트랙 비동기 분리 | 병목·유실 방지, 완전 자동화, 센서로 리소스 낭비 차단, 확장성 | DAG 의존성 설계 복잡도 |
| B. 수집 → 분석 → 다음 수집 순차 실행 | 단순 | 분석 지연이 다음 세트 수집을 막음 |

## 결정

**A 를 채택한다.**

- 오케스트레이션: Apache Airflow 로 전체 워크플로우의 의존성·실행 순서를 관리한다.
- 종료 시그널링: 게임 봇이 넥서스 파괴를 감지하면 S3 에 `{match_id}_finished.txt` 를 생성하고, `S3KeySensor` 가 이를 감지하여 다음 단계를 트리거한다.
- 비동기 실행: 다음 세트의 봇 실행 태스크(`run_game_bot_g5`)는 이전 세트의 분석 완료(`athena_analyze_g4`)를 기다리지 않고, 이전 세트의 '봇 실행'에만 의존성을 둔다. 정해진 휴식 시간(`wait_seconds`)이 지나면 분석 진행과 무관하게 다음 세트 수집을 병렬로 시작한다.

## 결과

- 좋아지는 것: 1세트 분석이 오래 걸려도 2세트 수집 봇은 정시에 켜지고, 사람 개입 없이 정산 보고서까지 S3 에 생성되며, 분석 로직이 무거워져도 수집 파이프라인 일정에 영향이 없다.
- 감수하는 것: DAG 의존성 설계.
- 다시 볼 조건: DAG 가 비대해져 역할별 분리가 필요할 때 (0050).
