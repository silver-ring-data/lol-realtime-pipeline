# 0046. Airflow와 S3 시그널링을 활용한 비동기 배치 분석 자동화

## 현상

- **실시간성과 영속성의 분리:** Flink를 통한 실시간 분석과는 별개로, 전체 경기 결과를 정산하고 장기 보관하기 위한 배치 작업(Batch Layer)이 필요함.
- **데이터 무결성 보장:** 경기가 진행 중일 때 배치를 돌리면 데이터가 누락될 수 있으므로, 반드시 '경기 종료'가 확인된 시점에 ETL 작업이 시작되어야 함.
- **수동 개입 최소화:** 봇 실행부터 데이터 정제(Glue), 최종 리포트 생성(Athena)까지의 전 과정을 자동화하여 운영 효율성을 높여야 함.
- **짧은 휴식 시간과 배치 지연의 충돌:** 프로 경기 세트 간 휴식 시간(약 15분)보다 배치 정산 작업이 더 오래 걸릴 경우, 다음 세트 데이터 수집에 지연이나 유실이 발생할 위험이 있음.

## 결정

- **오케스트레이션 도구:** **Apache Airflow**를 사용하여 전체 워크플로우의 의존성 및 실행 순서를 관리함.
- **종료 시그널링 전략:** 게임 봇이 넥서스 파괴를 감지하면 S3에 `{match_id}_finished.txt` 파일을 생성하고, Airflow의 `S3KeySensor`가 이를 감지하여 다음 단계를 트리거함.
- **수집과 분석 트랙의 의존성 분리 (비동기 실행):**
  - 다음 세트의 게임 봇 실행 태스크(`run_game_bot_g5`)는 이전 세트의 **'분석 완료(`athena_analyze_g4`)'를 기다리지 않음**.
  - 이전 세트의 '봇 실행'에만 의존성을 걸어두어, 세트 간 정해진 휴식 시간(`wait_seconds`)이 지나면 분석 진행 상황과 무관하게 즉시 다음 세트 수집을 병렬로 시작하도록 설계함.

## 이유

- **병목(Bottleneck) 및 데이터 유실 방지:** 1세트 분석에 아무리 오랜 시간이 걸려도 2세트 수집 봇은 정시에 켜지므로, 무중단으로 안전하게 실시간 데이터를 수집할 수 있음.
- **완벽한 자동화 (Hands-off):** 사람이 개입하지 않아도 Airflow가 종료 시점을 기다렸다가 정산 보고서까지 S3에 자동으로 생성함.
- **리소스 최적화:** 데이터가 다 쌓이지 않았는데 Glue Job이 먼저 돌아가는 리소스 낭비를 센서(Sensor)로 원천 차단함.
- **확장성:** 새로운 분석 지표가 추가되어 로직이 무거워지더라도, 메인 수집 파이프라인의 성능이나 일정에 전혀 영향을 주지 않음.
