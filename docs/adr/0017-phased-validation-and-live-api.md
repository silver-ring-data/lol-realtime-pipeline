# 0017. 단계별 파이프라인 검증 및 실전 API 확장 전략

> 원본: https://app.notion.com/p/3491198df8d98099ad75ca2370c8de02

| 상태 | 날짜 |
|---|---|
| 보류 | 2026-04-21 |

## 현상

- 우리는 실시간 롤 하이라이트 탐지 시스템의 신뢰성을 증명해야 합니다.
- 하지만 실제 API 데이터는 시차(3분 지연)와 불확실성(데이터 발생 여부)이 존재하여 초기 로직 개발 및 디버깅에 어려움이 있습니다.
- 따라서 안정적인 로직 구축과 실무 수준의 시스템 배포를 위해 단계별 접근 전략이 필요합니다.

## 결정

- 시스템 구축 과정을 [Phase 1: 로직 고도화 및 정적 검증]과 [Phase 2: 실전 API 연동 및 클러스터 배포]로 분리하여 시행합니다.

| **비교 항목** | **Phase 1 (1차 구현)** | **Phase 2 (2차 구현)** |
|---|---|---|
| **주요 대상** | 2024 월즈 결승 (T1 vs BLG) | 프로 선수 실시간 솔랭 및 방송 채팅 |
| **데이터 소스** | GOL.GG(게임), 유튜브 VOD(채팅) | Riot Spectator API, 실시간 스크래퍼 |
| **개발 환경** | Kinesis Studio Notebook (Interactive) | Apache Flink Application (JAR 배포) |
| **핵심 목표** | 하이라이트 판별 로직의 정확도 검증 | 시스템 가용성 및 시차(Skew) 해결 능력 증명 |
| **검증 포인트** | "한타 발생 시 점수가 폭등하는가?" | "3분 지연 데이터를 실시간 채팅과 맞추는가?" |

### **Phase 1: 정적 데이터를 통한 골든 데이터셋 검증**

- **이유:** 이미 정답(하이라이트 지점)이 알려진 과거 명경기 데이터를 사용하여 Flink의 윈도우 조인 및 스코어링 알고리즘을 정교하게 깎습니다.
- **방식:** 미리 준비된 JSON 파일을 Kafka에 Replay 하여 Studio Notebook에서 대화형으로 결과를 확인하며 로직을 튜닝합니다.

### **Phase 2: 실전 API 환경으로의 확장 (Production)**

- **이유:** 실제 야생(Wild) 데이터 환경에서 발생하는 네트워크 지연, API 할당량 제한, 시간차 문제를 해결하여 엔지니어링 역량을 극대화합니다.
- **방식:**
  1. Flink 코드를 JAR 파일로 패키징하여 Flink Cluster에 독립 실행형(Standalone) 앱으로 배포합니다.
  2. Riot API의 **3분 지연**을 처리하기 위해 Flink의 `Watermark`와 `Allowed Lateness` 혹은 `ProcessFunction`의 상태 관리를 적용합니다.
  3. 하이라이트 탐지 시 실시간 알림(Discord/Telegram) 연동 기능을 추가하여 실시간성을 시각화합니다.

## 이유

- **논리적 빌드업:** 시뮬레이션으로 로직의 정확도를 먼저 증명하고, 이후 실전 API로 확장했다는 서사는 프로젝트의 신뢰도를 높여줍니다.
- **기술적 차별화:** 단순히 데이터를 처리하는 것을 넘어, **'비정기적인 실시간 스트림 조인'**과 **'시간 지연 제어'**라는 고난도 문제를 해결한 경험을 포트폴리오에 담을 수 있습니다.
- **유지보수성:** 노트북 기반의 휘발성 코드가 아닌, 실제 배포 가능한 형태의 어플리케이션 구조를 확보하게 됩니다.
