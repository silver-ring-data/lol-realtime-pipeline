# 0053. 실시간 스트리밍 조인을 위한 수집 단계(Producer) 내 match_id 메타데이터 주입

## 현상

- **조인 키 부재:** 유튜브 등 외부 플랫폼에서 수집하는 채팅 데이터 원본에는 특정 경기(Match)를 식별할 수 있는 정보가 없음.
- **실시간 처리의 한계:** Flink에서 인게임 이벤트와 채팅을 결합(Join)하려면 공통 분모인 `match_id`가 필수적임.
- **스트림의 특성:** Kinesis 스트림은 S3 폴더 구조와 달리 데이터가 한 줄기로 흐르므로, 페이로드 내부에 식별자가 없으면 여러 경기가 섞일 때 데이터를 구분할 방법이 없음.

## 결정

- 데이터를 수집하여 Kinesis로 쏘는 파이썬 봇(Producer) 단에서 `match_id`를 메타데이터로 주입(Enrichment)하기로 결정함.
- 원본 데이터의 알맹이(내용, 닉네임)는 100% 유지하되, 봉투에 주소를 쓰듯 `match_id` 필드만 추가함.

## 이유

- **정확성 보장:** 수집 시점에 이미 해당 경기의 ID를 알고 있으므로, 사후에 추측하는 것보다 데이터 정합성이 완벽함.
- **Flink 로직 단순화:** Flink SQL에서 복잡한 윈도우 조인이나 억지스러운 `NULL` 처리를 걷어내고, 표준적인 `GROUP BY` 연산이 가능해짐.
- **실무 정석:** 데이터 수집 단계에서 시스템 운영에 필요한 메타데이터를 태깅하는 것은 'Data Enrichment'라는 표준적인 엔지니어링 기법임.
