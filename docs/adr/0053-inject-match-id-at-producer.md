# 0053. 실시간 스트리밍 조인을 위해 수집 단계(Producer)에서 match_id 메타데이터를 주입한다

## 배경

유튜브 등 외부 플랫폼에서 수집하는 채팅 원본에는 특정 경기(Match)를 식별할 정보가 없다. Flink 에서 인게임 이벤트와 채팅을 결합하려면 공통 분모인 `match_id` 가 필수다. Kinesis 스트림은 S3 폴더 구조와 달리 한 줄기로 흐르므로, 페이로드 안에 식별자가 없으면 여러 경기가 섞일 때 구분할 방법이 없다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. Producer 단에서 `match_id` 를 메타데이터로 주입(Enrichment) | 수집 시점에 ID 를 알고 있어 정합성 완벽, Flink 로직 단순화, 표준 기법 | 봇 코드 수정 |
| B. Flink 에서 시간·순서로 추측 | 봇 수정 불필요 | 억지스러운 NULL 처리, 부정확 |

## 결정

**A 를 채택한다.** 원본 데이터의 내용·닉네임은 100% 유지하되, 봉투에 주소를 쓰듯 `match_id` 필드만 추가한다.

## 결과

- 좋아지는 것: Flink SQL 에서 복잡한 윈도우 조인이나 NULL 처리 대신 표준적인 `GROUP BY` 연산이 가능하고, 데이터 정합성이 보장된다.
- 감수하는 것: 봇 코드 변경.
- 다시 볼 조건: 수집 시점에 경기 ID 를 알 수 없는 소스가 추가될 때.
