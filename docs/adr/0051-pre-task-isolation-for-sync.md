## 배경

파이프라인의 핵심은 인게임 이벤트와 채팅 화력을 동일 시간대(10초 윈도우)로 묶어 Flink 에서 실시간 조인하는 것이다. 기존에는 S3 찌꺼기 파일 삭제(`S3DeleteObjectsOperator`)와 Athena DDL 생성이 봇 실행 직전이나 루프 내부에 묶여 있었다. AWS API(S3, Athena) 응답 시간이 매번 불규칙(1초~수 초)하여 그 뒤의 봇들의 실제 송출 시작 시간이 밀렸고, 이 미세한 지연으로 게임·채팅 타임라인이 어긋나 Flink 워터마크가 꼬이고 데이터가 유실(Late Data Drop)되었다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 모든 인프라 준비 작업(Clean & Create)을 DAG 맨 처음(Entry Point)으로 이동 | 봇 출발 시간 동기화, 멱등성, 관심사 분리 | DAG 전체 시작 시간이 준비 작업만큼 늦어짐 |
| B. 봇 직전·루프 내 준비 작업 유지 | 변경 없음 | 불규칙한 지연으로 싱크 붕괴 |

## 결정

**A 를 채택한다.** 시간이 불규칙하게 소요되는 준비 작업을 메인 스트리밍 흐름에서 완전히 떼어내고, S3 경로 정리와 DDL 생성이 봇 스케줄링보다 훨씬 전에 독립적으로 완료되도록 의존성(`>>`)을 재설계한다.

## 결과

- 좋아지는 것: 사전 작업 지연이 봇 실행에 영향을 주지 않아 Flink 윈도우 조인 정합성이 보장되고, 재실행 시 항상 깨끗한 상태에서 시작하며, 인프라 세팅과 데이터 송출이 분리되어 디버깅이 쉽다.
- 감수하는 것: 준비 작업만큼의 선행 시간.
- 다시 볼 조건: 준비 작업이 별도 DAG(0050 의 DAG 1)로 완전히 분리될 때.
