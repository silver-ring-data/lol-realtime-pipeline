# 0051. 실시간 스트림 조인 싱크(Sync) 보장을 위한 사전 작업(Pre-task) 분리 및 집중화

## 현상

- 우리 파이프라인의 핵심은 '인게임 이벤트'와 '채팅 화력'을 동일한 시간대(10초 윈도우)로 묶어 Flink에서 실시간 조인(Window Join)하는 것임.
- **문제 발생:** 기존에는 S3 찌꺼기 파일 삭제(`S3DeleteObjectsOperator`)와 Athena DDL 생성 쿼리 작업이 봇 실행(Producer) 직전이나 루프 내부에 묶여 있었음.
- **치명적 결과 (Sync Delay):** AWS API 호출(S3, Athena)의 응답 시간이 매번 불규칙하여(1초~수 초 지연), 그 뒤에 연결된 **파이썬 봇들의 실제 데이터 송출 시작 시간이 밀리는 병목 현상**이 발생함. 이 미세한 지연 때문에 게임 데이터와 채팅 데이터의 타임라인이 어긋나 Flink의 워터마크(Watermark)가 꼬이고 데이터가 유실(Late Data Drop)되는 현상이 나타남.

## 결정

실시간 데이터의 완벽한 '출발 시간 동기화'를 보장하기 위해, 시간이 불규칙하게 소요되는 **모든 인프라 준비 작업(Clean & Create)을 메인 스트리밍 흐름에서 완전히 뜯어내어 DAG의 맨 처음(Entry Point)으로 몰아넣는다.**

- S3 경로 정리 및 테이블 뼈대(DDL) 생성은 봇이 스케줄링되기 훨씬 전에 독립적으로 완료되도록 의존성(`>>`)을 재설계함.

## 이유

- **완벽한 타임 싱크 (Zero Delay):** 사전 작업의 지연이 봇 실행에 영향을 주지 않게 됨. 봇들이 방해물 없이 정확한 밀리초 단위로 데이터를 쏘기 시작하여, Flink 윈도우 조인의 정합성이 100% 보장됨.
- **멱등성(Idempotency) 확보:** 파이프라인 재실행 시 항상 깨끗한 상태에서 시작하므로 이전 데이터와의 충돌 방지.
- **관심사의 분리:** '인프라를 세팅하는 작업'과 '실시간 데이터를 흘려보내는 작업'이 명확히 분리되어 디버깅이 쉬워짐.
