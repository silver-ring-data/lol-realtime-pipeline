# 0019. 대시보드 실시간 채팅 시각화를 위한 스마트 샘플링 도입

> 원본: https://app.notion.com/p/34a1198df8d980f29198eab0f317f964

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-04-22 |

## 현상

- **목표:** '온라인 응원석'이라는 프로젝트 컨셉을 극대화하기 위해, 프론트엔드 대시보드에 유저들의 실시간 채팅 로그를 노출하여 현장감을 제공하고자 함.
- **문제점:**
  1. **프론트엔드 과부하 (Performance):** 교전(하이라이트) 발생 시 1초에 수천 개의 채팅(Raw Data)이 쏟아지며, 이를 브라우저에 100% 렌더링할 경우 메모리 초과 및 프리즈(Freeze) 현상이 발생함.
  2. **데이터 품질 (Data Quality):** 원본 데이터(Bronze)에는 무의미한 도배성 채팅, 초성("ㅇㅇ", "ㅋㅋ"), 그리고 심한 욕설이 포함되어 있어 서비스의 퀄리티를 저하시킴.

## 결정

**모든 채팅 데이터를 브라우저로 직접 쏘는 대신, Flink 파이프라인 내에서 '3단계 스마트 샘플링(Smart Sampling)'을 거친 정제된 데이터(Silver)만 RDS를 통해 프론트엔드로 서빙한다.**

- **Step 1. 기본 수질 필터링 (Basic Filter):**
  - 글자 수 제한 (2자 이하, 50자 이상 컷)
  - 금칙어(욕설, 비하 단어) 맵핑을 통한 1차 Drop
- **Step 2. 키워드 부스팅 (Keyword Boosting):**
  - "대상혁", "펜타킬", "미쳤다" 등 긍정적이고 화력이 강한 특정 응원 키워드가 포함된 채팅에 가중치(우선권) 부여
- **Step 3. 초당 랜덤 추출 (TPS Throttling):**
  - 필터링과 부스팅을 통과한 알짜배기 채팅 중, **1초당 20~30개(브라우저가 쾌적하게 렌더링할 수 있는 최대치)**만 랜덤 추출하여 DB로 적재.

## 이유

- **시스템 안정성 확보:** 데이터 엔지니어링(Flink) 단에서 데이터 유입량을 통제(Throttling)함으로써, 최종 서비스(웹 브라우저 및 서빙 DB)의 장애를 원천 차단함.
- **UI/UX 기획 의도 달성:** 무의미한 텍스트 대신 열광적인 반응의 채팅들만 화면에 빠르게 올라가게 연출함으로써, 적은 리소스로도 최적의 '온라인 경기장 응원석' 분위기를 조성할 수 있음.

## 트레이드오프

- **장점:**
  - 웹 페이지 렌더링 성능 최적화 및 서빙 비용(RDS 쿼리 비용) 절감.
  - 악성 유저의 채팅 도배 공격(Spam)을 파이프라인 단에서 방어 가능.
- **단점 (Trade-off):**
  - Flink 내부에 필터링 및 가중치 부여 로직이 추가되어 스트림 처리 로직이 다소 복잡해짐. (하지만 Flink의 윈도우/필터 기능을 다루는 엔지니어링 역량을 어필할 좋은 기회가 됨)
