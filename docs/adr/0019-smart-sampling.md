# 0019. 대시보드 실시간 채팅 시각화에 스마트 샘플링을 도입한다

> 원본: https://app.notion.com/p/34a1198df8d980f29198eab0f317f964

| | |
|---|---|
| 상태 | **채택** |
| 날짜 | 2026-04-22 |
| 결정자 | silver-ring-data |
| 관련 | 0031, 0037 |

## 배경

'온라인 응원석' 컨셉을 위해 프론트엔드에 실시간 채팅 로그를 노출하려 한다. 그러나 교전 시 1초에 수천 개의 채팅이 쏟아져 브라우저에 전부 렌더링하면 메모리 초과·프리즈가 발생하고, 원본(Bronze)에는 도배성 채팅, 초성, 욕설이 섞여 서비스 품질을 떨어뜨린다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. Flink 내 3단계 스마트 샘플링 후 정제 데이터(Silver)만 서빙 | 렌더링 성능·서빙 비용 최적화, 스팸 방어, 응원석 분위기 연출 | Flink 스트림 로직 복잡도 증가 |
| B. 모든 채팅을 브라우저로 직접 전송 | 단순 | 프론트엔드 과부하, 품질 저하 |

## 결정

**A 를 채택한다.**

- Step 1. 기본 필터: 글자 수 제한(2자 이하, 50자 이상 제외), 금칙어 맵핑으로 1차 Drop
- Step 2. 키워드 부스팅: 화력이 강한 응원 키워드가 포함된 채팅에 가중치(우선권) 부여
- Step 3. TPS Throttling: 통과한 채팅 중 1초당 20~30개(브라우저가 쾌적하게 렌더링할 수 있는 최대치)만 랜덤 추출하여 DB 에 적재

## 결과

- 좋아지는 것: 데이터 엔지니어링 단에서 유입량을 통제하여 최종 서비스 장애를 원천 차단하고, 열광적인 채팅만 화면에 올라가는 연출을 달성한다.
- 감수하는 것: Flink 필터링·가중치 로직 복잡도.
- 다시 볼 조건: 프론트엔드 렌더링 한계치가 바뀌거나 필터 기준이 재정의될 때 (0031, 0037).
