# 0022. 시청자 수 연동을 제외하고 1차 MVP 스코프를 조정한다

## 배경

'디지털 트윈 응원석'의 아바타 밀도를 표현하려면 실시간 동시 시청자 수가 필요하다. 그러나 시청자 수는 폴링(Polling) 데이터이고 채팅/인게임은 스트리밍 데이터라 Flink 에서 결합(Interval Join)하기 어렵다. 또한 MVP 검증용 과거 VOD(2024 롤드컵 결승)는 타임라인별 시청자 수를 API 로 제공하지 않는다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 시청자 수 연동 제외, 분당 채팅 빈도(Chat Velocity/RPM)를 대용 지표로 사용 | 100% 실제 수집 데이터만 사용, 핵심 파이프라인에 집중 | 실제 시청자 수와 차이 |
| B. 가짜 시청자 수 생성 | 구현 쉬움 | 데이터 엔지니어링 신뢰도 저하 |
| C. 실시간 시청자 수 폴링 + Flink 결합 | 실제 값 | 기술 난이도 높음, VOD 에서는 불가 |

## 결정

**A 를 채택한다.** 1차 MVP 에서 실시간 시청자 수 API 연동을 제외하고, 분당 채팅 발생 빈도를 유저 인게이지먼트의 대용 지표(Proxy Metric)로 채택하여 아바타 밀도와 응원 화력 게이지에 비례 적용한다. 실제 시청자 수 폴링·결합은 Phase 2 로 분리한다.

## 결과

- 좋아지는 것: 데이터의 진실성을 지키고, 채팅·인게임 스트림 윈도우 조인이라는 핵심 과제에 우선순위를 둔다.
- 감수하는 것: 시청자 수라는 직관적 지표가 빠진다.
- 다시 볼 조건: 실시간 API 연동 시. (0041 에서 스케일 다운 시뮬레이션으로 방향이 바뀌며 폐기되었다.)
