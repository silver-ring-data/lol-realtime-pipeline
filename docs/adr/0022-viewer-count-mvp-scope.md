## 현상

- '디지털 트윈 응원석'의 아바타 밀도를 표현하기 위해 '실시간 동시 시청자 수' 데이터가 필요해짐.
- 그러나 시청자 수는 주기적으로 가져와야 하는 '폴링(Polling)' 데이터이며, 채팅/인게임은 쏟아지는 '스트리밍(Streaming)' 데이터임. 이 둘을 Flink에서 결합(Interval Join)하는 것은 기술적 난이도가 높음.
- 또한, MVP 검증용으로 사용할 과거 VOD 데이터(2024 롤드컵 결승)는 특정 타임라인별 시청자 수 기록을 API로 제공하지 않아 실시간 시뮬레이션에 제약이 있음.

## 결정

- 1차 MVP(Phase 1) 구현 범위에서 **'실시간 시청자 수 API 연동'을 제외**함.
- 가짜 시청자 수 데이터를 임의로 생성하는 대신, 기수집된 **'분당 채팅 발생 빈도(Chat Velocity/RPM)'를 유저 인게이지먼트(열기)의 대용 지표(Proxy Metric)로 채택**하여 아바타 밀도와 응원 화력 게이지에 비례 적용함.
- 실제 시청자 수 폴링 및 Flink 결합은 Phase 2(향후 고도화 과제)로 분리함.

## 이유

- 데이터의 진실성: 가상의 모의 데이터를 생성하는 것은 '데이터 엔지니어링'의 신뢰도를 낮출 위험이 있음. 100% 실제 수집된 데이터(채팅 빈도)만으로 현장감을 표현하는 것이 엔지니어로서 더 논리적이고 당당한 접근임.
- 복잡도 관리 (Scope Management): 1차 목표인 '채팅 스트림과 인게임 이벤트 스트림의 Flink 윈도우 조인' 자체도 난이도가 높으므로, 핵심 파이프라인의 안정적인 완성을 우선순위에 둠.
