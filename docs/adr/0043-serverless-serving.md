## 배경

'실시간 롤 응원석'은 경기 진행 여부나 하이라이트 발생 시점에 따라 트래픽 스파이크가 빈번하다. 고정 사양 EC2 를 24시간 운영하면 경기가 없는 시간에도 비용이 발생해 한정된 예산(6만 원) 관리가 어렵고, OS 업데이트·패치·스케일링을 직접 관리하는 것은 소규모 팀에 과도한 부담이다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. S3 + CloudFront(프론트) / API Gateway + Lambda(백엔드) | Pay-as-you-go, 자동 확장, 인프라 관리 시간 절약 | Lambda Cold Start |
| B. EC2 기반 서버 | 익숙함 | 고정 비용, 운영 부담 |

## 결정

**A 를 채택한다.**

- 프론트엔드: 빌드된 정적 리소스를 S3 에 호스팅하고 CloudFront CDN 으로 저지연 배포한다.
- 백엔드 API: 요청이 들어올 때만 Lambda 가 깨어나 OpenSearch(및 RDS)에서 데이터를 조회해 응답한다.
- 보안·최적화: CloudFront 로 S3 직접 접근을 차단(OAI/OAC)하고, API Gateway Throttling 으로 비정상 요청을 방어한다.

## 결과

- 좋아지는 것: 경기가 없는 시간의 비용을 0에 가깝게 유지, 결승전급 동시 요청에도 자동 확장, CloudFront 엣지 캐싱으로 응답 속도 향상, Flink 로직 고도화에 시간 투자.
- 감수하는 것: Cold Start. 가벼운 Python 코드 위주라 수백 ms 이내로 제어 가능하다.
- 다시 볼 조건: 상시 트래픽이 많아져 서버리스 비용이 고정 서버를 넘어설 때.
