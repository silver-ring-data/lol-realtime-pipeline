## 배경

Flink SQL, Athena 등 파이프라인 내부에서 사용하는 가상 테이블의 레이어를 직관적으로 알 수 있는 규칙이 필요했다. (노션 원문의 배경·이유 항목은 비어 있다.)

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `{layer}_{data}_{type}` 패턴 | 레이어·데이터·형태를 이름으로 식별 | - |

## 결정

**A 를 채택한다.** 패턴은 `{layer}_{data}_{type}` 이다.

- layer: 메달리온 단계 (`brz`, `slv`, `gld`)
- data: 데이터 종류 (`chat`, `match`, `event`)
- type: 리소스 형태 (`strm` 스트림 소스, `file` S3 적재용, `rds` DB 테이블)

## 결과

- 좋아지는 것: 테이블 이름만으로 레이어와 용도를 파악한다.
- 감수하는 것: -
- 다시 볼 조건: 배치·스트리밍 레이어가 분리되어 더 세분화된 규칙이 필요할 때 (0049).
