# 0034. 경기 종료 시점(넥서스 파괴) 기준 스트림 처리 자동 종료 및 동기화 전략

> 원본: https://app.notion.com/p/3521198df8d98057a1b7cfe799bfba90

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-04-30 |

## 현상

- 우리 파이프라인에는 명확한 시작과 끝이 있는 '게임 데이터(Bounded)'와 24시간 끊임없이 흐르는 '채팅 데이터(Unbounded)'가 동시에 유입됨.
- 경기가 끝난 후(넥서스 파괴 이후) 발생하는 "수고하셨습니다", "ㅂㅂ" 등의 채팅 로그는 하이라이트 분석에 무의미함.
- 그럼에도 이 무의미한 채팅 데이터를 Flink가 계속 연산하고 파이프라인을 태울 경우, **하이라이트 지표의 정확도 하락**과 **불필요한 클라우드 리소스/비용(Kinesis, Flink, S3) 낭비**가 발생함.
- 따라서 '게임이 끝났음'을 시스템 전체가 인지하고, 분석 파이프라인을 깔끔하게 종료(Graceful Shutdown)할 수 있는 트리거(Trigger)가 필요함.

## 결정

게임 데이터 내의 **`"victim_id": "NEXUS DESTROYED"`** 이벤트를 파이프라인의 '경기 종료 트리거'로 공식 지정하며, 수집(Producer)과 분석(Analytics) 단에서 다음 두 가지 조치를 취하기로 결정함.

- **[수집 단] 봇(Producer) 기반 상태 플래그 생성:** `game_bot.py`가 넥서스 파괴 이벤트를 감지하는 즉시, Kinesis 전송을 종료하고 S3의 특정 경로(`status/{match_id}_finished.txt`)에 '경기 종료 깃발(상태 파일)'을 업로드함.
- **[분석 단] 타임스탬프 기반 채팅 컷오프(Cut-off):**
  - **실시간(Flink):** 넥서스 파괴 이벤트의 Timestamp 이후에 들어오는 채팅 데이터는 윈도우 조인 연산에서 즉시 무시(Drop)하도록 필터링 조건 추가.
  - **배치(Athena):** S3에 쌓인 채팅 데이터를 쿼리할 때, 넥서스 파괴 시간 이전(`chat_time <= nexus_destroyed_time`)의 데이터만 대상으로 스캔하여 비용 최적화.

## 이유

- **자동화된 서버리스 오케스트레이션(Orchestration):** S3에 `finished.txt`가 올라가는 행위 자체를 이벤트 트리거로 삼아, 대기하고 있던 후속 배치 작업(Lambda -> Glue 정산 Job)을 자동으로 깨울 수 있음.
- **데이터 정합성 확보:** 하이라이트 화력 점수에 경기 후의 무의미한 반응이 섞이는 것을 차단하여 지표의 신뢰도를 극대화함.
- **비용 최적화(Cost-Effectiveness):** 경기가 끝난 직후 쓸데없는 데이터의 스트리밍 및 적재를 즉시 차단하여, 불필요한 Kinesis 및 Firehose 트래픽 비용을 절감함.
