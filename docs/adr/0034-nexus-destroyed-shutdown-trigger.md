# 0034. 넥서스 파괴 시점을 기준으로 스트림 처리를 자동 종료하고 동기화한다

> 원본: https://app.notion.com/p/3521198df8d98057a1b7cfe799bfba90

| | |
|---|---|
| 상태 | **채택** |
| 날짜 | 2026-04-30 |

| 관련 | 0046, 0050 |

## 배경

파이프라인에는 시작과 끝이 명확한 게임 데이터(Bounded)와 24시간 흐르는 채팅 데이터(Unbounded)가 동시에 유입된다. 경기 종료(넥서스 파괴) 이후의 "수고하셨습니다" 같은 채팅은 하이라이트 분석에 무의미하지만, 이를 계속 연산하면 지표 정확도가 떨어지고 Kinesis·Flink·S3 비용이 낭비된다. '게임이 끝났음'을 시스템 전체가 인지하고 파이프라인을 깔끔하게 종료(Graceful Shutdown)할 트리거가 필요하다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. `"victim_id": "NEXUS DESTROYED"` 이벤트를 종료 트리거로 지정 | 데이터 정합성, 비용 절감, 후속 배치 자동 트리거 | Producer·Flink·Athena 세 곳에 로직 추가 |
| B. 수동 종료 또는 고정 시간 종료 | 단순 | 경기마다 길이가 달라 부정확 |

## 결정

**A 를 채택한다.**

- 수집 단: `game_bot.py` 가 넥서스 파괴를 감지하면 Kinesis 전송을 종료하고 S3 `status/{match_id}_finished.txt` 에 '경기 종료 깃발'을 업로드한다.
- 분석 단(실시간, Flink): 넥서스 파괴 타임스탬프 이후의 채팅은 윈도우 조인에서 즉시 무시(Drop)한다.
- 분석 단(배치, Athena): `chat_time <= nexus_destroyed_time` 데이터만 스캔한다.

## 결과

- 좋아지는 것: S3 에 종료 파일이 올라가는 행위 자체가 후속 배치(Lambda → Glue)를 깨우는 서버리스 오케스트레이션이 되고, 경기 후 무의미한 반응이 지표에 섞이지 않으며, 불필요한 트래픽 비용이 줄어든다.
- 감수하는 것: 세 지점에 종료 로직을 유지한다.
- 다시 볼 조건: 연속 세트 경기에서 종료·시작 신호가 겹칠 때 (0046).
