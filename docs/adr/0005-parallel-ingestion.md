# 0005. 실시간성 확보를 위한 병렬 데이터 수집 아키텍처 채택

| 채택 | 2026-04-14 |

## 현상

- 초기 설계(AI 제시)에서는 데이터의 정합성을 위해 **경기 지표 수집(Match Data) 완료 후 채팅 데이터(Chat Log)를 수집**하는 순차적(Sequential) 파이프라인을 검토함.
- 하지만 롤(LoL) 경기는 인게임 상황과 유저의 반응이 **실시간으로 동기화**되어야 하는 도메인 특성을 가짐.
  - **지연 시간 발생:** 경기 데이터 수집 태스크가 종료될 때까지 채팅 수집이 대기하게 되면, 실시간 채팅 데이터의 **골든타임(Live Window)**을 놓치게 됨.
  - **분석의 불일치:** 두 데이터의 수집 시점이 어긋나면, 나중에 "특정 한타 상황"과 "그때의 민심"을 타임스탬프 기준으로 매칭하기 어려워짐.

## 결정

지휘관 역할을 하는 **`Master Commander DAG`**를 도입하여, 경기 시작 감지 즉시 두 개의 서브 파이프라인을 **병렬(Parallel)로 트리거**하는 구조로 변경함.

- **기술적 구현:** Airflow의 `TriggerDagRunOperator`를 리스트 형태로 배치하여 비동기 실행을 보장함.
- **동기화 전략:** 각 수집기는 독립적으로 작동하되, 데이터 적재 시 서버 표준 시간(UTC)을 타임스탬프로 기록하여 결합성을 확보함.

## 트레이드오프

- **장점:**
  - 실시간 스트리밍에 적합한 **저지연(Low Latency)** 데이터 수집 가능.
  - 파이프라인 간의 의존성을 낮추어(Decoupling) 한쪽 수집기에 장애가 발생해도 다른 쪽은 영향을 받지 않음.
- **단점:**
  - 동시 실행에 따른 리소스(Worker) 부하가 증가할 수 있으나, 현재 트래픽 규모에서는 관리 가능한 수준임.
