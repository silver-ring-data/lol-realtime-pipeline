# 0005. 실시간성 확보를 위해 병렬 데이터 수집 아키텍처를 채택한다

|---|---|

## 배경

초기 설계에서는 정합성을 위해 경기 지표 수집이 끝난 뒤 채팅을 수집하는 순차(Sequential) 파이프라인을 검토했다. 그러나 LoL 경기는 인게임 상황과 유저 반응이 실시간으로 동기화되어야 하는 도메인이다. 순차 수집은 채팅의 골든타임(Live Window)을 놓치고, 두 데이터의 수집 시점이 어긋나 타임스탬프 기준 매칭이 어려워진다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. Master Commander DAG 가 두 서브 파이프라인을 병렬 트리거 | 저지연 수집, 파이프라인 간 결합도 감소 | 동시 실행에 따른 Worker 부하 증가 |
| B. 순차 수집 | 단순한 의존성 | 지연 발생, 분석 시점 불일치 |

## 결정

**A 를 채택한다.** 경기 시작 감지 즉시 Airflow `TriggerDagRunOperator` 를 리스트 형태로 배치하여 비동기 실행을 보장한다. 각 수집기는 독립적으로 동작하되 적재 시 서버 표준 시간(UTC)을 타임스탬프로 기록하여 결합성을 확보한다.

## 결과

- 좋아지는 것: 저지연 수집이 가능하고, 한쪽 수집기 장애가 다른 쪽에 영향을 주지 않는다.
- 감수하는 것: 동시 실행에 따른 리소스 부하. 현재 트래픽 규모에서는 관리 가능한 수준이다.
- 다시 볼 조건: Worker 리소스가 부족해질 때.
