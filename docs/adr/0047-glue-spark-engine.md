# 0047. 배치 레이어 데이터 처리를 위한 Glue Spark 엔진 채택

> 원본: https://app.notion.com/p/3561198df8d98023a30bca92283ff97d

| 상태 | 날짜 |
|---|---|
| 채택 | 2026-05-04 |

## 현상

- 우리 프로젝트의 메달리온 아키텍처에서 **Bronze(JSON) 데이터를 Silver/Gold(Parquet)로 변환 및 정제**하는 배치 작업이 필요함.
- AWS Glue Job에서 선택할 수 있는 옵션은 크게 두 가지임:
  - **Python Shell:** 가볍고 저렴하지만 단일 노드 메모리에 종속적임.
  - **Glue Spark (PySpark):** 분산 처리 엔진으로 대용량 처리에 최적화되어 있으나 비용이 상대적으로 높음.
- AI 교육 과정에서 배운 Pandas/Polars(중소용량)와 Spark(대용량)의 기준점 사이에서, 우리 프로젝트의 '데이터 엔지니어링적 가치'를 극대화할 수 있는 엔진을 선택해야 함.

## 결정

- 단순한 파이썬 스크립트 기반의 Python Shell 대신, 분산 엔진인 Apache Spark(PySpark)를 Glue Job의 메인 엔진으로 채택한다.

## 이유

- **무한한 확장성(Scalability) 증명:** 현재 샘플 데이터는 작지만, 실제 LCK 결승전 같은 수천만 건의 트래픽 상황에서도 코드 수정 없이 Worker(Node)만 늘려 대응할 수 있는 '빅데이터 처리 설계'를 보여주기 위함임.
- **데이터 레이크 최적화 (Parquet 변환):** Spark는 열(Column) 기반 저장 포맷인 Parquet 변환에 최적화되어 있음. 이를 통해 나중에 **Athena 분석 비용을 90% 이상 절감**하는 '선투자 후회수' 전략을 취함.
- **데이터 엔지니어링 직무 역량 어필:** 단순 스크립트 작성을 넘어, 현업 데이터 파이프라인의 표준인 Spark 환경에서의 트러블슈팅과 분산 아키텍처 이해도를 포트폴리오에 녹여내기 위함임.
- **효율적 리소스 관리:** Spark가 비싸다는 단점은 **최소 DPU(2개) 설정**과 **작업 완료 후 즉시 파기**하는 설계를 통해 하루 커피 한 잔 값 이하로 방어 가능함.

## 트레이드오프

- **장점:** "데이터 규모에 상관없이 버티는 시스템"이라는 엔지니어링 신뢰도 확보. Athena 쿼리 효율성 극대화.
- **트레이드오프:** Python Shell보다 약 2배 정도의 기본 비용이 발생하지만, 이는 Athena 비용 절감분과 엔지니어링 학습 가치로 충분히 상쇄됨.
