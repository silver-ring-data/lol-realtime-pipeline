## 배경

메달리온 아키텍처에서 Bronze(JSON)를 Silver/Gold(Parquet)로 변환·정제하는 배치 작업이 필요하다. AWS Glue Job 옵션은 크게 Python Shell(가볍고 저렴하지만 단일 노드 메모리 종속)과 Glue Spark(분산 처리, 대용량 최적화, 상대적으로 고비용)다. Pandas/Polars(중소용량)와 Spark(대용량)의 기준점 사이에서 프로젝트의 데이터 엔지니어링 가치를 극대화할 엔진을 선택해야 한다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. Glue Spark (PySpark) | 코드 수정 없이 Worker 확장, Parquet 변환 최적화로 Athena 비용 90% 이상 절감, 현업 표준 경험 | Python Shell 대비 약 2배 기본 비용 |
| B. Python Shell | 저렴, 단순 | 단일 노드 메모리 한계 |

## 결정

**A 를 채택한다.** 비용은 최소 DPU(2개) 설정과 작업 완료 후 즉시 파기하는 설계로 하루 커피 한 잔 값 이하로 방어한다.

## 결과

- 좋아지는 것: "데이터 규모에 상관없이 버티는 시스템"이라는 신뢰도, Athena 쿼리 효율 극대화, Spark 트러블슈팅 경험.
- 감수하는 것: 약 2배의 기본 비용. Athena 절감분과 학습 가치로 상쇄된다.
- 다시 볼 조건: 데이터 규모가 계속 작게 유지되어 Spark 오버헤드가 부담이 될 때.
