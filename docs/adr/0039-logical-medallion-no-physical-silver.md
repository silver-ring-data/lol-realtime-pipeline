# 0039. 실시간 트랙에서 물리적 Silver 저장소를 제거하고 논리적 Medallion 명명을 유지한다

> 원본: https://app.notion.com/p/3541198df8d980c3b7a2cc99ae2dbf9f

| | |
|---|---|
| 상태 | **채택** |
| 날짜 | 2026-05-03 |
| 결정자 | silver-ring-data |
| 관련 | 0030, 0036 |

## 배경

Flink SQL 에서 실버 레이어를 `VIEW` 로 분리하여 시간 보정·정제를 수행하면 시간 속성(Watermark)이 유실되어 골드 레이어의 윈도우 조인이 불가능해지는 기술적 제약을 확인했다. 또한 Speed Layer 에서 단계마다 Kinesis 에 물리적으로 쓰고 읽는 행위는 지연과 비용을 늘린다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 물리적 Silver 생략, 인메모리 서브쿼리/인라인 정제, 결과물은 'Gold' 로 명명 | 워터마크 보존, 실버용 Kinesis 비용 100% 절감, 1초 미만 응답 | 중간 데이터가 없어 디버깅 난이도 상승 |
| B. 물리적 Silver 스트림/폴더 유지 | 중간 데이터 추적 가능 | 워터마크 유실, 지연·비용 증가 |

## 결정

**A 를 채택한다.** 봇 메시지 제거, 필드 타입 변환, 시간 보정 로직을 골드 집계 쿼리의 서브쿼리 또는 인라인 처리로 통합한다. 메달리온 아키텍처의 핵심은 물리적 저장소 개수가 아니라 데이터 품질·가치의 단계이므로, 정제와 분석이 완료된 'Ready-to-serve' 결과물은 Gold 로 명명하는 것이 타당하다.

## 결과

- 좋아지는 것: 워터마크 유실 에러가 해결되어 끊김 없는 하이라이트 탐지가 가능하고, 예산 내 운영이 가능하다.
- 감수하는 것: 디버깅 난이도. Flink Checkpointing 과 CloudWatch 로그로 보완한다.
- 다시 볼 조건: 중간 단계 데이터를 별도 소비자가 필요로 할 때.
