# 0027. 하이라이트 탐지 윈도우(Window) 및 가중치(Weight) 파라미터를 최적화한다

## 배경

Flink 로 인게임 이벤트(Fact)와 채팅(Sentiment)을 윈도우 조인하는 로직을 구현했다. 어떤 시간 간격으로 묶을지, 이벤트와 채팅 밀도의 가중치를 어떻게 배분할지에 따라 하이라이트 점수 정확도가 크게 달라진다. 2024 롤드컵 결승전 6시간 분량, 77,000건 이상의 채팅 데이터를 기반으로 최적 파라미터를 도출해야 했다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 10초 윈도우 / 3초 슬라이드 + 이벤트·채팅 가중 합산 | 1초 미만 지연 목표에 부합, 연속 교전·지연 반응 포착 | 채팅 수집량은 긴 윈도우보다 적음 |
| B. 30초 등 긴 윈도우 | 더 많은 채팅 수집 | 실시간성 저하 |

## 결정

**A 를 채택한다.** 데이터 분석·시뮬레이션 결과를 토대로 다음과 같이 정한다.

- 윈도우: `WINDOW_SIZE` = 10초, `SLIDE_STEP` = 3초, `CHAT_LOOKBACK` = 2초 / `CHAT_LOOKAHEAD` = 8초 (이벤트 기준 과거 2초~미래 8초를 Interval Join)
- 이벤트 가중치: `BARON_KILL` 40 > `DRAGON_KILL` 25 > `CHAMPION_KILL` 20 > `TOWER_BUILDING_KILL` 15
- 채팅 밀도 점수: 10초 내 100개 이상 = 100점 / 51개 이상 = 50점 / 21개 이상 = 20점
- 최종 합산: `(Event Score * 0.6) + (Chat Score * 0.4)` — 가벼운 교전이라도 시청자 반응이 뜨거우면 '슈퍼플레이'로 포착하도록 민심 지수에 40% 영향력 부여

Flink SQL 최상단에 하이퍼파라미터 구역을 분리하여 재배포 없이 튜닝할 수 있게 구조화한다.

## 결과

- 좋아지는 것: 킬이 발생하지 않았으나 관중 호응이 극에 달한 '비정형 하이라이트'(예: 존야 플레이)를 추출할 가능성을 확보하고, 다른 종목·스트리머 방송에도 파라미터만 바꿔 적용할 수 있다.
- 감수하는 것: 파라미터는 단일 경기 기준이므로 추가 검증이 필요하다.
- 다시 볼 조건: 다른 경기·종목 데이터로 검증할 때.
