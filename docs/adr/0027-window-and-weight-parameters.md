# 0027. 하이라이트 탐지 윈도우(Window) 및 가중치(Weight) 파라미터 최적화

> 원본: https://app.notion.com/p/34f1198df8d98035a83dfc58f00d86eb

| 상태 | 날짜 |
|---|---|
| 보류 | 2026-04-27 |

## 현상

- Apache Flink를 활용하여 인게임 이벤트(Fact)와 채팅 데이터(Sentiment)를 실시간으로 결합(Window Join)하는 로직을 구현함.
- "어느 정도의 시간 간격(Window)으로 묶을 것인지", "각 이벤트와 채팅 밀도의 가중치를 어떻게 배분할 것인지"에 따라 하이라이트 점수의 정확도가 크게 달라짐.
- 실제 2024 롤드컵 결승전(T1 vs BLG) 6시간 분량, 77,000건 이상의 채팅 데이터를 기반으로 최적의 파라미터를 도출해야 했음.

## 결정

데이터 분석 및 시뮬레이션 결과를 토대로 다음과 같이 하이퍼파라미터를 결정함.

- **윈도우 크기 및 슬라이딩 간격 (Window Settings)**
  - `WINDOW_SIZE` = 10초: 인게임 이벤트 발생 후 대중의 반응(채팅)이 가장 밀집되는 핵심 시간대.
  - `SLIDE_STEP` = 3초: 10초 윈도우를 3초마다 슬라이딩시켜, 연속적인 교전이나 지연된 채팅 반응도 놓치지 않고 포착하도록(Overlapping) 설정.
  - `CHAT_LOOKBACK` = 2초 / `CHAT_LOOKAHEAD` = 8초: 인게임 이벤트 발생 시점 기준으로 과거 2초(예측/놀람)부터 미래 8초(폭발적 반응)까지를 하나의 의미 있는 반응 구간으로 조인(Interval Join)함.
- **이벤트 가중치 (Event Weights)**
  - `BARON_KILL` (40점) > `DRAGON_KILL` (25점) > `CHAMPION_KILL` (20점) > `TOWER_BUILDING_KILL` (15점)
  - 단순 킬 교환보다, 게임의 판도를 뒤집는 오브젝트(바론, 용) 획득에 더 높은 가중치를 부여하여 '기세 지표'의 신뢰도를 높임.
- **채팅 밀도 점수 (Chat Levels)**
  - 10초 내 채팅 100개 이상 = 100점 / 51개 이상 = 50점 / 21개 이상 = 20점
  - 결승전 채팅 평균 발생률(TPS)과 하이라이트 구간의 극단적인 Traffic Spike 편차를 고려하여, 100개 이상을 '극적 하이라이트(민심 대폭발)' 기준으로 설정함.
- **최종 합산 비율 (Final Ratio)**
  - `(Event Score * 0.6) + (Chat Score * 0.4)`
  - 가벼운 교전이라도 시청자 반응(Chat)이 뜨거우면 '슈퍼플레이'로 포착할 수 있도록 민심 지수에 40%의 영향력을 부여함.

## 이유

- **유연성(Flexibility) 확보:** 향후 다른 e스포츠 종목(예: 발로란트)이나 일반 스트리머 방송에 적용할 때, 이 파라미터 값들만 수정하면 시스템 전체를 재배포하지 않고도 쉽게 튜닝이 가능하도록 구조화함.

## 트레이드오프

- **실시간성과 정확도의 트레이드오프:** 윈도우 사이즈를 늘리면(예: 30초) 더 많은 채팅을 수집할 수 있지만 실시간성이 떨어짐. 10초 윈도우와 3초 슬라이딩의 조합이 "1초 미만의 지연 시간(Low Latency) 내에 유의미한 민심을 포착한다"는 프로젝트 목표에 가장 부합함.

### **결과 및 영향 (Consequences)**

- 해당 파라미터 적용 결과, "페이커 존야 플레이" 등 인게임 지표로는 킬(Kill)이 발생하지 않았으나 관중의 호응이 극에 달한 **'비정형 하이라이트'**를 성공적으로 추출해낼 가능성이 존재
- Fink SQL 내에 설정값(Hyperparameters) 구역을 최상단으로 분리하여 파이프라인의 유지보수성과 실험(Simulation) 효율을 극대화함.
